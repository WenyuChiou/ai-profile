# ai-profile v0.7.0 Automation Layer Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship the v0.7.0 automation layer: a batch `aiprofile refresh --out DIR [--dry-run]` application service that re-scans every configured repository and republishes the exact eight-file dist bundle atomically (never on partial failure); a stdlib-only `aiprofile schedule install|status|remove` command with narrow Windows Task Scheduler / macOS launchd / Linux systemd-user adapters driving a single-instance launcher that refreshes, stages exactly the eight dist paths, commits only those paths and only on byte change, and pushes by default with an explicit non-force push to the branch and remote recorded at install time; and a public-only reusable GitHub Actions workflow (package version and destination hard-coded per release tag) plus a copyable caller template for users whose scanned repositories are all public. All default output — refresh stdout/stderr, lock errors, scheduler CLI errors, and the scheduler's last-run log — identifies repositories by config ordinal and aggregate counts only: no paths, no repository names, no basenames (a verbose local-only mode is future work; the v0.7.0 default never exposes names). The maintainer Profile keeps using the local scheduler (its config includes an `aggregate_only` repository, which the public Action must never scan). No ACE schema, aggregation, `VizStats`, renderer, or eight-output contract change of any kind.

**Architecture:** Two new application-layer modules above the existing pipeline, plus one workflow pair. `src/aiprofile/lockfile.py` provides a cross-platform nonblocking per-`AIPROFILE_HOME` advisory lock (msvcrt on Windows, fcntl elsewhere). `src/aiprofile/refresh.py` is an orchestration service in cli.py's layer: it may import `scanner`, `aggregate`, `privacy`, `render.*`, `export`, `config`, `storage`, `errors`, `lockfile` — renderers and exporters stay pure and keep consuming validated `VizStats` only; refresh adds no new render or privacy behavior, it sequences existing behavior (scan all → aggregate once → render once → `export.write_outputs` once). Dry-run builds a shadow home under the already-held home lock: `config.json` is copied, and the database is snapshotted with sqlite3's online backup API (`Connection.backup()` from a read-only source connection into a fresh shadow-path connection) so committed WAL content is included — never a raw copy of the main DB file alone; rendering happens in memory, so the real home and output directory are never touched. `src/aiprofile/schedule/` holds the CLI service (`service.py`), the launcher payload writer (`launcher.py` template written under `AIPROFILE_HOME/scheduler/`), and per-OS adapters (`adapters/windows.py`, `adapters/launchd.py`, `adapters/systemd.py`) that only build argv lists and file payloads — all process execution goes through `subprocess.run(list, shell=False)`; nothing is ever interpolated into a shell string. Windows registers via a Task Scheduler XML definition (`schtasks /Create /XML`, separate `Command`/`Arguments`, LeastPrivilege current-user interactive token, `MultipleInstancesPolicy=IgnoreNew`, `StartWhenAvailable=true` — never a fragile `/TR` command string); launchd serializes its plist with stdlib `plistlib.dumps`. `schedule install` refuses a detached HEAD and records the profile repo's current branch and remote name (names only — never URLs or tokens) into scheduler config. The launcher is native single-instance (its own nonblocking lock under `AIPROFILE_HOME/scheduler/`), refuses to run if the checked-out branch no longer matches the recorded branch, calls the refresh service, then stages/commits exactly the eight dist paths with git pathspec-limited commits so pre-staged unrelated index content can never ride along, and pushes with the explicit non-force `git push <recorded remote> HEAD:<recorded branch>`. `.github/workflows/profile-refresh.yml` is a `workflow_call`-only reusable workflow (public repos only; validated public repository identifiers as the ONLY input; identities as a required secret; ephemeral home in `RUNNER_TEMP`; the released PyPI version `0.7.0` and the caller destination `dist` hard-coded inside the workflow so the caller controls neither; split read-only build job / least-privilege commit job); `docs/templates/profile-refresh-caller.yml` is the copyable caller pinned to `@v0.7.0`, with a non-top-of-hour schedule, `workflow_dispatch`, and a separate least-privilege Pages deploy job (required because `GITHUB_TOKEN` commits do not trigger push/Pages workflows) that checks out the UPDATED default branch after the refresh commit and publishes `_site/dist` containing exactly the eight outputs. Static workflow-contract tests in the style of `tests/unit/test_release_workflow_contract.py` / `test_staging_preview.py` pin every guardrail.

**Tech Stack:** Python ≥ 3.11 stdlib only (no new runtime dependencies: `msvcrt`/`fcntl`, `subprocess`, `argparse`, `json`, `sqlite3` `Connection.backup()` for the dry-run DB shadow, `plistlib` for the launchd plist — no hand-written XML templates or `xml.sax.saxutils.escape` anywhere; the Windows task definition is built with `xml.etree.ElementTree`), system `git` ≥ 2.17, `schtasks.exe` / `launchctl` / `systemctl --user` invoked via argv, pytest + Ruff, GitHub Actions with all official actions pinned by full commit SHA (reuse the exact pins already in `.github/workflows/ci.yml`; the Pages trio in the caller template uses the current verified pins listed in Task C2).

## Frozen scope guards (read before every task)

- **Never touch:** `src/aiprofile/schema/`, `aggregate.py`, `privacy.py`, `viz.py`, `render/*`, the eight-name allowlist in `export.py`, ACE schema version `0.3.0`. No model-by-day inference anywhere. Renderers remain pure functions of `VizStats`.
- Sanctioned snapshot commands (`python tests/unit/test_render_summary.py`, `python tests/unit/test_heatmap_svg.py`) must produce **zero diff** at every gate — if they don't, a task violated the freeze.
- No network code in `src/aiprofile/` and no network in any test, ever (ADR-011). The only network surface added is inside GitHub Actions YAML.
- Every code fix for a review finding lands red-first (regression proven failing pre-fix) per AGENTS.md.
- **Default-output privacy rule (applies to every task):** all default `refresh` stdout/stderr, lock errors, scheduler CLI errors, and scheduler last-run log lines are path-free and repository-name-free — repositories are identified by config ordinal (e.g. `repository 2 of 3`) and aggregate counts only. Basenames and display names are NOT allowed identifiers in default output. Config necessarily stores the profile path under `AIPROFILE_HOME`, but no log or default console line ever prints it. A verbose/local-only mode may relax this in a future version; v0.7.0 ships without it.
- **Pre-commit review sequence (MANDATORY for every commit, before `git commit` runs):** (1) Codex independently reviews the UNCOMMITTED diff; (2) the code-review skill AND the code-reviewer subagent both run on that same uncommitted diff; (3) every finding is fixed (code fixes red-first) and re-reviewed until clean; (4) only Fable stages and commits — staging is explicit per-path `git add <path>` with a `git diff --cached --name-only` count assertion (never `git add .`/`-A`), and the commit carries the repo's AI trailer block (AGENTS.md "Commit trailers"): blank line before the block, no blank line inside it. The FIRST review always happens on the uncommitted diff before the commit exists — never deferred until after push. After commits exist: push the PR branch, wait for green CI, then the committed-range independent gate review (Task E3) before merge.
