Date: 2026-08-04<br>

Reviewer posture: independent Principal Software Engineer; verification only

## Executive summary

The rejected perspective/3D summary treatment has been replaced by a flat,
static 2D daily matrix. The renderer still accepts only validated `VizStats`,
keeps the existing eight-output contract, and preserves the aggregation and
privacy boundaries. The daily matrix has 84 neutral tracks; published days add
bottom-anchored bars whose height is the unique day's total-commit bin and
whose fill is the AI-share bin. Provider overlap cannot increase bar height.

The candidate is technically green in local verification and visually legible
in light and dark themes. It is not yet an official release: the branch still
needs the normal PR/CI review, cross-platform release run, tag/artifact
publication, and the separate Profile refresh after the candidate is released.

## Findings

### Medium — candidate is not yet a published release

**Description:** The flat design is on `codex/v050-flat-evidence-ledger`; the
repository's public PyPI/Profile state is still the previously released
v0.4.8 artifact; no tag or Profile deployment was changed in this review.

**Impact:** Users will not receive the new flat card until the candidate goes
through the repository's PR, CI, release, and Profile refresh workflow.

**Recommendation:** Merge only after independent review and required CI are
green, build and verify one immutable wheel/sdist pair, publish a new version,
then regenerate the maintainer Profile from that exact wheel and run the live
HTTP/privacy/determinism checks.

### Low (closed) — historical perspective references are retained intentionally

**Description:** Older ADRs, changelog entries, and prior gate reports retain
the perspective design because they document what was released or reviewed at
that time. ADR-022 now explicitly states that ADR-025 supersedes its
perspective daily-visual clauses; current architecture, MVP, roadmap, README,
renderer comments, and ADR-025 identify the flat matrix as active.

**Impact:** A reader searching all history may still see both designs, but the
ADR status and source-of-truth links prevent a contract ambiguity.

**Recommendation:** Keep the historical records immutable; use ADR-025 and
`DESIGN.md` as the active source of truth.

## Verified areas without findings

- **Architecture:** renderer remains a pure presentation layer; no Git,
  SQLite, storage, network, or attribution inference was added.
- **Schema and aggregation:** `DayCell.total_commits` controls volume bars,
  AI-share controls fill hue, and provider counts never enter geometry. The
  existing unknown/human and provider-overlap semantics remain intact.
- **Privacy:** no new identity-bearing fields or public paths were introduced;
  release smoke and the existing integration privacy suites remain green.
- **Determinism/security:** integer coordinates, static allowlisted SVG,
  no scripts/handlers/external references, and byte-stable sanctioned outputs.
- **Maintainability:** retired prism helpers and guide hooks were removed
  rather than left as unused compatibility abstractions; the shared bin helper
  remains the single source for volume/share thresholds.
- **Onboarding/docs:** English and Traditional Chinese README structure and
  privacy claims remain in parity; the visual description now names the flat
  activity matrix.
