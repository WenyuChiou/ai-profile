# Structural Current visual readiness review

Date: 2026-08-04
Review target: `codex/v050-structural-current` after `cefaad0` plus seam-guide remediation
Reviewer posture: independent principal-engineering verification plus
independent design-forensics and browser smoke

## Executive summary

The Structural Current slice is technically safe and visually stronger while
remaining inside the v0.4.8 renderer contract. The summary now has a faint
integer guide scaffold on the tile seams after the existing daily prisms; the dashboard uses
neutral section markers and a small warning rule instead of a large yellow
unattributed panel. No ACE/schema field, aggregation unit, privacy field,
CLI command, dependency, network request, or output filename changed.

The slice is **GO WITH CONDITIONS** for a public patch: the code and local
candidate artifact are ready for a versioned release round, but the branch has
not yet been merged, tagged, published, or used to regenerate the maintainer
Profile from a new released wheel. Calling the current bytes a new public
release would overstate what was verified.

## Research basis

Independent read-only forensics are recorded in
[`design-reverse-engineering.md`](design-reverse-engineering.md) and the raw
reports under `.coord/research/`. The adapted principles are evidence-first
hierarchy, semantic role tokens, explicit privacy/fallback language,
chart/label parity, and progressive detail. Terminal telemetry, glass/aurora,
remote fonts, animated 3D, hosted analytics, and source-style inference were
explicitly rejected. The maintainable visual contract is [`DESIGN.md`](../../DESIGN.md)
and ADR-024.

### Independent visual-review remediation

The first independent visual pass identified a Medium concern that centerline
guides could be hidden behind opaque prisms and a Low concern that the test
only exercised the helper. Both are resolved in the current working tree:
guides now follow tile boundaries, shared seams are emitted once, and guides
are emitted after all terrain faces. `test_terrain_section_precedes_the_provider_ledger`
asserts the 21 unique guide nodes and their ordering against the complete
expected terrain polygon region.

## Findings

### Medium — M-01: release identity is still v0.4.8

**Description:** `pyproject.toml`, runtime metadata, frozen candidate evidence,
and the current public release remain `0.4.8`; this branch is not a new tag or
PyPI artifact.

**Impact:** Users installing the released wheel will not receive the new
visual bytes, and publishing the same immutable filename would be incorrect.

**Recommendation:** From a clean release branch, bump the patch version,
move the notes out of `Unreleased`, rebuild once in the canonical environment,
run Twine/artifact/clean-wheel/cross-platform checks against those exact bytes,
then tag and publish only after CI is green.

### Medium — M-02: maintainer Profile still points at the prior release

**Description:** The Profile repository and its Pages deployment are pinned to
the already released v0.4.8 wheel and assets.

**Impact:** The new design is not publicly visible from the real Profile until
the release candidate is installed and the separate Profile PR is regenerated,
privacy-swept, merged, and Pages-verified.

**Recommendation:** After M-01, regenerate all eight Profile artifacts from the
same downloaded wheel in an isolated Profile branch; keep the existing
publication policy and run the byte-level privacy and link checks before merge.

### Low — L-01: design tokens remain intentionally split by output format

**Description:** SVG `Theme` tokens and dashboard CSS variables are represented
in their native renderer formats rather than one runtime token loader.

**Impact:** A future palette change could drift if it is made in only one
renderer.

**Recommendation:** Keep the current dependency boundary for this release.
When a second real consumer requires shared values, add a small typed token
source and parity tests in a separate ADR; do not add a framework or registry
just to remove this documentation-level duplication.

## Verified areas without findings

- Architecture and dependency direction: renderer/export isolation remains
  intact; no new abstraction crosses the privacy boundary.
- Aggregation semantics: no calculations changed; unique commits, presences,
  provider counts, active days, evidence records, and unknown remain disjoint.
- SVG/static dashboard security: no active content, remote assets, or network
  path was added; output remains deterministic and self-contained.
- Accessibility: visible labels, numeric denominators, non-color selection
  cues, focus, responsive reflow, and reduced-motion behavior remain present.
- Documentation: ADR-024, `DESIGN.md`, plan, research record, roadmap,
  progress, and changelog describe only the presentation change and its
  release condition.
- OSS readiness: README quickstart and bilingual parity remain green; the
  design research is linked through repository docs without changing the
  pinned public-link evidence set.
