## Executive summary

`ai-profile` v0.6.0 is ready for Public Beta use. The release adds a stable,
contrast-checked visual key for canonical model families in the existing
Summary Card and self-contained dashboard. It does not change the ACE schema,
aggregation units, CLI, privacy boundary, or eight-output contract.

The model ledger is intentionally all-time and non-exclusive: one commit may
appear in more than one model-family row when the evidence contains multiple
models. Unknown remains a separate neutral row. The daily activity matrix does
not infer model categories; its geometry remains unique daily commits and its
fill remains daily AI share. This preserves the project's aggregation
semantics instead of manufacturing a model-by-day statistic that is not in the
validated aggregate.

All release gates are closed: **667 passed, 4 skipped**, Ruff clean, README
parity pass, sanctioned snapshot regeneration byte-stable, exact-wheel smoke
pass, cross-platform CI/onboarding pass, browser and privacy checks pass, and
the exact wheel/sdist are live on PyPI and GitHub. The GitHub Release is
explicitly a prerelease and PyPI remains Beta; this is public beta, not GA.

## Architecture and data review

- The renderer still receives validated `VizStats` only. It does not scan Git,
  read SQLite, access the network, infer attribution, or recalculate totals.
- Model-family colors are a presentation-only scale in the render layer. The
  palette is canonical, deterministic, local-fallback, and contrast-checked
  for both themes. Provider colors and model colors do not leak into ordinary
  text, and labels do not depend on color alone.
- Unique commits, actor presences, provider involvement, active days, model
  involvement, evidence records, and unknown/human attribution remain distinct
  aggregation units. The model ledger explicitly documents its non-exclusive
  counting rule.
- The daily matrix remains provider/model independent. A future model-by-day
  view requires a validated cross-dimension aggregate and an ADR; the renderer
  must not infer it from all-time rows.
- Public artifacts contain canonical family labels only. Raw model strings and
  repository-local identifiers remain behind the existing privacy boundary.

## Findings

### Medium — release metadata was initially vulnerable to stable/prerelease drift (closed)

**Description:** The first v0.6.0 publication created a GitHub Release without
the prerelease flag even though the project and PyPI metadata describe a 0.x
Public Beta. The state was independently observed and repaired with
`gh release edit v0.6.0 --prerelease` before the release was announced.

**Impact:** A stable-looking GitHub badge could overstate support guarantees
and contradict the README, changelog, and PyPI classifier.

**Recommendation:** Keep the workflow guard that passes `--prerelease` on
creation and explicitly repairs existing releases. The contract test now
asserts both paths. **Disposition: closed; current release is
`isPrerelease=true`.**

### Low — model categories are not a dated time series (accepted by design)

**Description:** The model-family ledger is all-time and non-exclusive; the
daily matrix does not expose Claude/GPT/etc. by day.

**Impact:** Users cannot answer a model-by-date question from the current
dashboard, but adding a renderer-side inference would double-count or invent
data that `VizStats` does not validate.

**Recommendation:** Keep the current honest boundary. Add a dated model
cross-dimension aggregate only through a future schema/ADR change with its own
privacy and reconciliation tests. **Disposition: accepted; not a release
blocker.**

No Critical or High findings remain open. No privacy, schema, aggregation,
determinism, packaging, cross-platform, or accessibility blocker was found.
